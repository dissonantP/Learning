The Agent Harness Is Turning Into a Control Plane

Tool permissions, audit trails, cost budgets, subagents and hooks are converging into something that looks much more like infrastructure orchestration than a chat wrapper.

Production agent systems are accumulating familiar control-plane responsibilities. Anthropic’s recent deployment material describes guardrails at every tool call and exporting traces and audit events into ordinary cloud observability systems. Its advanced Claude Code material treats subagents, hooks and MCP connections as the mechanisms for parallel work, policy enforcement and tool chaining.

Monitoring and securing agents at scale · Claude Code advanced patterns

A useful systems analogy

The emerging architecture resembles Kubernetes more than a chatbot: the model is a worker capable of proposing actions; the harness owns scheduling, capabilities, lifecycle, budgets, state boundaries and evidence. MCP-style tools then resemble dynamically discoverable service interfaces. Hooks behave like admission controllers or lifecycle middleware. Sandboxes provide execution isolation. Tracing provides the audit plane.

The analogy is imperfect but useful because it tells you where not to put policy. A prompt saying “do not modify production” is comparable to asking a process politely not to call a privileged syscall. The enforceable boundary belongs outside the model.

Cost belongs in the control plane too

Once agents can spawn agents, retry automatically and run on schedules, token cost becomes a resource-allocation problem rather than a billing afterthought. Per-agent budgets, maximum fan-out, retry ceilings and model routing are analogous to quotas. The interesting observability metric becomes cost per established invariant or completed workflow, not simply tokens per conversation.

What to watch

The next important layer is likely declarative agent policy: capabilities, data boundaries, verifier requirements, allowed fan-out, escalation rules and budgets represented as configuration the runtime can enforce. That would make an agent workflow reproducible in the same way infrastructure-as-code made server configuration reproducible.
