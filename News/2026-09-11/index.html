MCP lost the session — and gained an infrastructure boundary

The July 28 protocol revision removes the handshake and protocol-level session, pushes durable state into explicit application objects, and makes ordinary gateways much more useful for routing, authorization, tracing, and failure recovery.

The important consequence is architectural: MCP becomes a thinner capability layer while orchestration state moves into workflows, databases, supervisors, and explicit handles.

The dangerous part of an MCP tool may be its description

Tool-poisoning research shows that malicious metadata can manipulate an agent into invoking a different, legitimate high-privilege tool. Discovery itself is becoming a trust boundary.

Practical pattern

Separate discovery from execution

A useful permission model has at least four steps: inventory a tool, expose its metadata to the model, allow the model to propose a call, and actually execute it. “Server enabled” is too coarse.
