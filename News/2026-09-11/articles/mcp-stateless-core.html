AI agent infrastructure

MCP lost the session — and gained an infrastructure boundary

The July 28, 2026 MCP revision is less a protocol cleanup than a change in where agent systems are expected to keep state, route requests, authorize operations, and survive failure.

September 11, 2026

The largest recent change in Model Context Protocol is architectural rather than cosmetic. MCP 2026-07-28 removed the initialize/initialized handshake and the protocol-level session ID. Each request now carries the information needed to stand on its own, and an optional server/discover call replaces the old assumption that a long-lived client/server session has already established capabilities.

That sounds like ordinary HTTP hygiene, but it changes the shape of production agent infrastructure. A request can land on any server instance behind a normal round-robin load balancer. Tool and method names can be surfaced in headers for gateways. Tool catalogs can be cached. Sticky sessions and shared protocol-session storage are no longer prerequisites for remote MCP deployment.

The useful mental model is: MCP became stateless, not agent applications. Durable state now has to be explicit.

State moves upward into the application

A browser automation tool still needs a browser session; a shopping tool still needs a cart; a workflow still needs a durable execution record. The difference is that these are now application objects passed explicitly as IDs or handles, rather than ambient state smuggled through a protocol session.

For orchestration systems, this is a strong separation of concerns. The MCP server can become a horizontally replaceable capability endpoint, while a Temporal workflow, agent supervisor, database record, or other orchestration object owns durable state and recovery. That makes retries and failover easier to reason about because the thing that must survive is named rather than implied.

Server-to-client interaction is being converted into round trips

The old model let a server issue requests such as sampling or elicitation while handling a client request. The modern design moves toward Multi Round-Trip Requests: the server returns an input_required result containing the requested input and opaque continuation state; the client satisfies it and replays the original operation with the response attached.

This matters operationally because it avoids holding an open bidirectional stream while a human or model responds. It also means a long-lived agent operation can cross process boundaries more cleanly: the continuation becomes data that can be queued, persisted, traced, and resumed.

Several once-core features are deliberately shrinking

Roots, Sampling, and Logging were formally deprecated under SEP-2577. Sampling is particularly revealing. Earlier MCP designs entertained servers asking the client’s model to perform completions, even with tools. The newer direction is narrower: servers expose capabilities; model-provider interaction belongs elsewhere.

This reduces MCP’s ambition as an agent runtime while strengthening it as an interoperability layer. That is probably healthy. Protocols become easier to secure and operate when they do less invisible work.

Gateways become much more useful

The 2026 specification puts method and tool names into Mcp-Method and Mcp-Name headers. Combined with stateless requests, this lets ordinary infrastructure inspect and route agent actions without parsing arbitrary JSON bodies or remembering session history.

That opens a practical enforcement point for capability policy: “this identity may call search but not delete_customer,” rate limits per tool, audit logs at the gateway, and routing expensive tools to separate execution pools. In other words, an agent tool call starts looking more like an API operation that existing infrastructure knows how to govern.

What I would carry into an orchestration design

Keep durable workflow state outside MCP; treat every tool call as replayable unless explicitly documented otherwise; put authorization at the capability boundary rather than in prompts; and make tool-call correlation IDs first-class so a trace can follow one operation through orchestrator, MCP gateway, sandbox, and external API.

The notable trend is convergence with established distributed-systems practice. Agent infrastructure is becoming less exotic precisely where it is becoming more serious.
