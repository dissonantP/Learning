An agent's name is not its authority

Recent security work converges on a useful distinction: identity, capability, delegation and provenance are separate things. MCP makes that distinction operationally important.

A recurring weakness in agent infrastructure is assuming that authenticating an agent or tool server tells you what it is allowed to do. An agent can keep the same identity while acquiring a new tool, a tool can change after authorization, and delegated subagents can receive authority whose origin becomes difficult to reconstruct.

The capability-identity gap

Ziling Zhou's 2026 paper Governing Dynamic Capabilities names this failure mode. It proposes binding a hash of the skill manifest to the agent certificate, so changing the capability set invalidates the credential, plus a signed interaction ledger for later reconstruction. The prototype reports roughly 0.62 ms governance overhead per tool call.

The design lesson is simple: don't store “agent X is trusted.” Associate authorization with a particular principal, capability set, delegation chain and invocation.

Delegation needs attenuation

AIP: Agent Identity Protocol addresses delegation across MCP and A2A. Its Invocation-Bound Capability Tokens combine identity, authorization and provenance. Downstream holders can attenuate authority: a parent can delegate a narrower capability without handing over its full authority.

Connection: this resembles object-capability security more than ordinary application RBAC. A subagent should receive the minimum authority needed for its task rather than inherit the orchestrator's ambient permissions.

Layered controls

MCPSHIELD compares multiple MCP defenses and argues that capability control, tool attestation, information-flow tracking and runtime policy enforcement address different failure modes. The useful architectural point is that no single control substitutes for the others.

For a practical orchestrator, keep four things independently inspectable: who acted, what authority was granted, which tool implementation that grant referred to, and what happened. A transcript captures only part of this.

A concrete experiment

Represent every tool invocation as an append-only capability record: principal ID, tool version/digest, explicit scopes, parent delegation ID, sandbox ID, result artifact hashes and verifier outcome. Agent session trees then become provenance trees—and reveal when the authority tree and conversational tree diverge.

Sources: Zhou, 2026; Prakash, 2026; Acharya & Gupta, 2026.
