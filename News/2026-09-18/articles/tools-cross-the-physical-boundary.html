AI agent infrastructure · MCP

MCP crosses into the physical world

Google Home’s September MCP integration is a useful case study because tool permissions stop being abstract when a call can inspect cameras or make a speaker talk.

Google has opened parts of Google Home to third-party AI agents through Model Context Protocol. Reported capabilities include querying household state, analyzing camera history, troubleshooting devices, generating dashboards and sending voice notifications to speakers. The implementation also illustrates the first line of defense: rate limits and capability exclusions, including a restriction on unlocking doors.

This is a better mental model for agent permissions than “does the user trust Claude/OpenClaw/etc.?” Trusting an agent is too coarse. The relevant object is the capability grant: which operation, against which resource, under which conditions, with what persistence and audit trail.

A camera-history query, a thermostat change, a speaker announcement and a door unlock are all “tool calls” at the protocol layer. Their consequences are radically different. Protocol uniformity therefore increases—not decreases—the need for semantic authorization.

Preflight, runtime, aftermath

MCPShield, a 2026 research system, proposes a useful three-phase pattern for open MCP ecosystems: probe and assess a server before invocation; constrain and observe execution at runtime; then update trust from historical traces afterward. Whether or not that specific implementation survives, the separation is useful. Static allowlists cannot detect changed behavior; runtime isolation cannot decide whether an action was appropriate; logs without provenance cannot tell you which capability actually caused an effect.

The physical-home example adds another distinction: read capability can itself be high impact. Camera history and occupancy state do not mutate a device, but they expose intimate information. A permission system organized only around “read versus write” misses this.

Design implication for agent harnesses

A mature harness should make capabilities first-class objects rather than burying them inside tool schemas. Ideally a grant is narrow, inspectable, revocable and attributable to a particular task. Dangerous operations can then require elevation or human approval without forcing the entire server into an all-or-nothing trust bucket.

MCP’s success at connecting heterogeneous systems makes this more urgent. As the same agent interface expands from GitHub and databases into homes, browsers, payment systems and industrial equipment, the protocol’s ergonomic benefit—one generic way to call tools—creates a security obligation to preserve the differences between those tools elsewhere in the stack.
