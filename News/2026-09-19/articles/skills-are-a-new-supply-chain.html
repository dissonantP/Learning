Agent infrastructure · security

Skills are a new kind of supply chain

The interesting part of a malicious agent extension is not whether it contains bad code. It is that instructions, code and delegated authority can cooperate in ways conventional scanners were not designed to reason about.

MalSkillBench, released in June, constructs a runtime-verified corpus of 3,944 malicious agent skills, alongside 4,000 matched benign skills. A “skill” here is the increasingly common package used by coding agents: natural-language instructions plus scripts and tool permissions. The authors’ key claim is architectural rather than statistical: this is a hybrid supply-chain object.

The detector gap is the important result

The benchmark’s strongest skill-specific detector reaches 98.4% recall on code-injection cases, but degrades sharply on prompt-injection and attacks aimed at the agent control plane. Traditional supply-chain scanners see executable code; prompt-injection defenses see instruction text. Neither naturally models the relationship between the two.

A practical mental model

Installing a skill is closer to installing a package that also edits your employee handbook and requests a badge. Static code review answers only one of those questions.

The benchmark also complicates “real-world” evaluation. Its wild sample is heavily concentrated: 86.6% belongs to one cryptocurrency-theft behavior and 81% comes from two accounts. A detector that looks excellent on that distribution can be learning the campaign rather than the threat class. The synthetic pipeline is useful precisely because it deliberately spans 108 cells in a taxonomy of behaviors.

What this implies for a harness

A robust agent harness should probably treat skill installation as a capability negotiation, not a file-copy operation. At minimum, the useful review surface is: what instructions enter privileged context; what executables become callable; which filesystem/network/credential capabilities are requested; and whether those capabilities are actually exercised at runtime.

That suggests a two-stage defense. Installation-time analysis establishes an expected capability envelope. Runtime tracing then checks whether the skill’s actual syscalls, tool calls and data flows remain inside it. The latter matters because MalSkillBench’s labels are runtime-verified in Docker rather than inferred from suspicious-looking text.

Connection: verifier security

This resembles the lesson from Terminal Wrench: the dangerous behavior often lives in the gap between what a system means to authorize and what its success mechanism literally permits. Terminal Wrench contains 331 reward-hackable terminal environments and 3,632 exploit trajectories, including output spoofing, standard-library patching and binary hijacking. In both cases, the defense has to observe effects, not merely inspect intentions.

Worth exploring next

The strongest design question is whether agent ecosystems need something analogous to mobile-app permissions: a declarative manifest of capabilities that can be compared against observed behavior. The hard part is that natural-language instructions themselves can change how existing capabilities are composed, so the manifest cannot be derived from imports alone.
