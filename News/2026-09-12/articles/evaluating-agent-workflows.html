Agent benchmarks are finally testing workflows, not just answers

A useful 2026 benchmark exposes a recurring weakness in agent systems: basic tool execution can look solved while conditional branching and long-running orchestration still fall apart.

EngiAI, published in May, is interesting less because it introduces another multi-agent framework than because of how it evaluates one. The authors coordinate seven specialized agents through a supervisor architecture and test engineering workflows that include simulation, retrieval, SLURM jobs, and 3D-printer control. The benchmark deliberately separates different failure modes instead of compressing everything into one “success” number.

Paper: Molinari et al., EngiAI: A Multi-Agent Framework and Benchmark Suite for LLM-Driven Engineering Design (2026).

DimensionWhat it isolates
Workflow promptsTool use, semantic ambiguity, memory, and conditional branching
RAG gatingWhether correct parameter choices actually came from retrieval
HPC orchestrationWhether the system survives a genuinely multi-step external workflow
The striking result: conditional branching was dramatically harder than ordinary tool use, with completion dropping to roughly 20–53% in one benchmark setting.

Why conditional branches matter

Many agent demos are effectively linear: inspect → decide → call tool → inspect result → finish. Production workflows are not. They contain “if this job failed, inspect logs; if the error is transient, retry; if the input is malformed, route to a human; otherwise continue.” Each branch creates opportunities for the model to misread state, skip a precondition, or preserve the wrong context.

This suggests a useful design rule: encode control-flow invariants in the orchestrator whenever they are deterministic. The model can choose among meaningful alternatives, but it should not have to rediscover mundane workflow semantics from prose every run.

RAG gating is a good evaluation pattern

The paper’s retrieval experiment is also worth copying. Instead of merely asking whether an agent with RAG performs well, the benchmark gates the score so that it can distinguish an answer produced from retrieved evidence from an answer the model happened to know or guess. In their setup, retrieval-augmented runs approached perfect scores while the no-retrieval condition collapsed toward zero.

That is a general lesson for agent evaluation: test the contribution of each subsystem. If memory, retrieval, a verifier, or a tool broker is supposedly important, construct paired tasks where success should disappear when that component is removed.

A practical evaluation stack

For a coding or automation agent, a strong local benchmark suite would therefore include four layers: deterministic unit checks for tools; branch-heavy workflow scenarios; ablations that remove retrieval/memory/verifiers; and long-horizon runs where the system must resume after interruption. Those measurements tell you much more than a single end-to-end pass rate.
